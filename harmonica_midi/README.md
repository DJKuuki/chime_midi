# harmonica_midi：自动转写的 MIDI（草稿）

这里是仓库里全部 181 个发车铃 MP3 用 [Harmonica](https://arxiv.org/abs/2609.04640) 自动转写出来的 MIDI，目录结构和 MP3 一一对应（例如 `第一弹 001-026/001 JR-SH1.mid`）。这些是**草稿**：可以直接试听、导入 DAW 编辑，但需要人工校对。

## 怎么生成的

- 模型：[`harmonica-amt`](https://pypi.org/project/harmonica-amt/) 0.3.0，是 Harmonica 论文的第三方复现，不是 BandLab 的官方代码。转写时把 nano 和 small 两个模型的输出取平均，起音和持续阈值分别是 0.15 和 0.3。
- 格式：单轨钢琴（GM program 0），120 BPM。音符时间按秒对齐原录音，没有按节拍量化。力度由模型预测。
- 重新生成：见 [`tools/transcribe_harmonica.py`](../tools/transcribe_harmonica.py)。在 4 核 CPU 上，181 首约 90 秒，不需要 GPU。

## 准确率

测试方法：把仓库根目录的 11 个手工 MIDI 用 FluidR3_GM 音色库渲染成 MP3，因此每个音的正确答案都是已知的。这些 MIDI 的音色包括钢片琴、颤音琴、八音盒、Pad、FX 等。下表是音符起音 F1：起音误差在 ±50 ms 内且音高完全正确才算对；括号里是不计八度差别时的 F1。

| 测试条件 | Basic Pitch（调参后） | Harmonica nano | Harmonica small | **nano+small（本目录）** |
|---|---|---|---|---|
| 干净渲染 | 0.62 | 0.75 | 0.66 | **0.78** |
| 模拟车站广播（混响、扬声器频带、噪声） | 0.54 | 0.66 | 0.66 | **0.68** |
| 降半音并放慢（模拟「音が低い」一类版本） | 0.61 | 0.73 | 0.70 | **0.75** |
| 全部换成管钟音色 | 0.11 (0.50) | 0.09 (0.26) | 0.17 (0.55) | **0.18** (0.53) |
| 全部换成钟琴（Glockenspiel）音色 | **0.24** (0.29) | 0.10 (0.12) | 0.21 (0.32) | 0.22 (0.31) |
| 181 首真实录音里基本没转出来的文件数¹ | — | 11 | 0 | 0 |

¹ 指转出的音符数不到 Basic Pitch 的 30%。单用 nano 时，`希望の鐘`、`JR-SH3-1(東京ver)` 等录音几乎什么都识别不出来，所以本目录改用 nano 和 small 平均。

阈值 0.15/0.3 是在「干净渲染」这一组上选出来的，所以这一行的分数偏乐观；其余几行没有参与调参。

真实录音只有 `039 SF22-29(柏ver)` 能和手工 MIDI 可靠对齐：参考 MIDI 里的音大约有 61% 被找到。

## 已知问题

- **八度错误**：约 9–12% 的输出音符差一个八度，校对时优先检查。
- **长音被拆开**：Pad 一类的长音有约 8–12% 会被拆成几个重复音。
- **音长不可靠**：钟声的余音很长，建议只信音高和起音，按曲速量化后再修音长。
- **很轻的高音层容易漏**：例如 `048 farewell` 里的高音琶音。
- **纯钟声音色准确率低**：`希望の鐘`、`高原(鐘強調…)` 这类文件需要重点校对。
- **音域限制**：只能识别钢琴 88 键（A0–C8）以内的音。

## 关于这个模型

- Harmonica 论文来自 BandLab（Ou 等，2026，arXiv:2609.04640），官方没有发布代码和权重。这里用的 `harmonica-amt` 是个人（Zion Huang）做的复现，仓库里没有 LICENSE 文件，使用和再分发的授权情况不明确。
- 包里自带的 `.pt` 权重检查过：pickle 只引用 `torch._utils._rebuild_tensor_v2`、`torch.FloatStorage` 和 `collections.OrderedDict`，用 `torch.load(..., weights_only=True)` 能正常加载，不含可执行代码。
